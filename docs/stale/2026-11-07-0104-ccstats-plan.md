# ccstats — cross-machine Claude Code usage tracker

## Context
Soham runs two subscriptions (`claude` → `~/.claude`, `claudia` → `CLAUDE_CONFIG_DIR=~/.claudia`) on 4 personal
machines plus short-lived CloudLab nodes. Goal: daily/weekly stats on sessions & subagents, tokens, tool calls,
and "Claude time" (active time from a human prompt to control returning, excluding user-decision waits and
background work). Proposed shape (hub pulls transcripts from a host list on a schedule, parses, aggregates) is
right; this plan sharpens it based on what the transcripts actually contain.

## What the data gives us (verified on this machine, CC 2.1.3xx)
- Transcripts: `<cfg>/projects/<proj-slug>/<sessionId>.jsonl`; subagents in
  `<sessionId>/subagents/agent-<id>.jsonl` + `agent-<id>.meta.json` with `agentType`, `spawnDepth`,
  `toolUseId`, `model`, worktree info → depth / team size come for free.
- `assistant` records: one per content block, so `message.usage` repeats — **dedupe by `message.id`**
  (hamlet session: 1511 records, 755 ids → naive sum would double-count).
- `usage`: input, cache_read, cache_creation (5m/1h), output, `output_tokens_details.thinking_tokens`.
- Human prompts: `type=user` with `origin.kind == "human"` (vs `task-notification`, `peer`, tool results).
- `api-request` records (timestamp = request start, `querySource`), `tool_use` blocks, `toolUseResult`
  (has `isAsync`/`backgroundTaskId` for background work), `queue-operation`, `compact_boundary`.
- `system/turn_duration` is **not usable** for Claude time: sparse (28 per ~840 user records) and includes
  hours of background waiting (values of 2.4h, 8.2h).
- `cost-state` (cumulative per session) — good cross-check for token totals, not for daily splits.
- **Neither settings.json sets `cleanupPeriodDays`** → CC deletes transcripts after 30 days. `~/.claude`
  already shows only a handful of sessions. Archiving raw files is therefore the core requirement.

## Design
Two strictly separated stages; stats are always a pure function of the raw archive.

1. **collect** — `rsync -a` (no `--delete`) of `~/.claude/projects` and `~/.claudia/projects` from each host
   into `archive/<host>/<profile>/projects/…` on the hub. Files are append-only JSONL, so rsync is cheap and
   incremental; offline hosts are skipped and retried next run; remote cleanup never loses archived data.
   Skip `tool-results/`, `file-history`, `memory/` (bulk, not needed).
2. **compute** — Python 3 stdlib only (no jq on hosts; parsing runs only on the hub). Re-parse changed files
   (cache keyed on path+size+mtime → per-file event rows in SQLite), then aggregate. Parser fixes are applied
   retroactively just by rerunning.
3. **report** — daily + ISO-weekly aggregates from SQLite, written to `report.json`, then two outputs:
   - CLI: `ccstats report [--week] [--host H] [--profile P]` terminal tables; plus a static `report.html` on hub.
   - claude.ai dashboard artifact: the deterministic pipeline can't call the Artifact tool, so a separate
     daily timer runs a tiny headless `claudia -p` job that republishes the dashboard from `report.json`
     (it's the only step that uses the model; small, cheap, and its own usage is tagged and excluded from stats).
     At implementation, start it from the Dashboard Artifact type via quickstart.

Inventory: `hosts.toml` — per host: ssh target, `mode = pull|push`, profiles present, and for CloudLab
`kind = "cloudlab"` + `proj = "<project>"`. `ccstats host add|rm|ls`; `ccstats pull <host>` for a manual grab.

**Hub + push fallback** (chosen). Hub = this machine (assumed reachable by ssh hostname from the others,
e.g. via Tailscale. Confirm during setup).
- Pull: hub timer (hourly) rsyncs from every `mode=pull` host; unreachable hosts are logged and retried.
- Push: `ccstats push` (single stdlib script, installed via dotfiles) runs from a systemd user timer/cron on
  `mode=push` hosts (NAT'd/sleeping laptops) and rsyncs into the hub's same `archive/<host>/<profile>/` path.
  Pull and push write identical paths with rsync temp+rename, so they're idempotent and can overlap.
- **CloudLab via /proj** (chosen): `ccstats cloudlab-setup` (run once per node, or from the experiment
  profile's startup script) moves `~/.claude/projects` and `~/.claudia/projects` to
  `/proj/<project>/ccstats/<node-fqdn>/<profile>/projects` and symlinks them back. Transcripts outlive the node;
  the hub pulls the whole `/proj/<project>/ccstats/` tree from `ops.<cluster>` or any live node, so individual
  nodes never need to be in the inventory.

Scheduling: systemd user timers (hub: collect+compute hourly; push hosts: push hourly), via home-manager/flake
if dotfiles are nix-managed. Also set `cleanupPeriodDays: 3650` in both settings.json on every host via
dotfiles as a second safety net.

## Metric definitions
Day = local date of each *event* (not session start), so sessions spanning midnight split correctly.
Dimensions on every row: host, profile (claude/claudia), project, model.

1. **Sessions**: main sessions active that day; subagents spawned (count, by `agentType`); team size =
   subagents per session and peak concurrent subagents (spawn→finish intervals); max/mean `spawnDepth`.
2. **Tokens** (deduped by message.id, main + subagents, reported separately): input, output, thinking,
   cache_read, cache_write; plus totals, per-session and per-active-day averages. Cache reads dominate
   (~99% in hamlet) so totals are shown both with and without them.
3. **Tool calls**: count by tool name; Bash commands counted, with leading executable extracted
   (`git`, `cargo`, …) for a top-N; background vs foreground; errors (`is_error`).
4. **Claude time** (main thread only) = per human prompt, the union of
   - API in-flight intervals: `api-request.timestamp` → last assistant record of that response, and
   - foreground tool intervals: `tool_use` → matching `tool_result`,
   excluding: tool calls that are user decisions (`AskUserQuestion`, `ExitPlanMode`), async/background tool
   launches beyond their launch, and gaps after the turn ends (waiting for task-notifications).
   Also report "agent-time" = same union over each subagent, summed (parallel work).
   **Human waits**: almost all are decision tools (AskUserQuestion / ExitPlanMode). Their tool_use →
   tool_result interval is exactly the wait (verified: this session's question = 18:35:51 → 18:43:54) and is
   dropped. Tool-approval prompts are rare, so other foreground tool time counts as-is, with a
   safety cap (`approval_cap`, default 10 min, configurable) only on intervals where permissionMode was
   `default`, so a forgotten approval prompt can't add hours. Also report *API time* (model in-flight only)
   alongside Claude time as an exact lower bound.

## Layout
`~/dev/ccstats/` (flake.nix, `ccstats` CLI: `collect`, `compute`, `report`, `host add|rm|ls`, `pull`),
`ccstats/parse.py` (record → events), `ccstats/metrics.py` (aggregation SQL), `hosts.toml`,
data in `~/.local/share/ccstats/{archive,ccstats.db}`.

## Verification
- Unit fixtures: trimmed real JSONL snippets (multi-block assistant message, subagent meta, async Agent
  launch, compact boundary) with hand-computed expected numbers.
- Cross-check token sums per session against that session's `cost-state.modelUsage` (should match exactly).
- Claude-time sanity: run a scripted session (`claudia -p` with a known sleep-free prompt) and compare to
  stopwatch; run one with a deliberate 2-min wait at a permission prompt / AskUserQuestion and confirm it's
  excluded.
- End-to-end: `ccstats collect` against this machine + one remote, kill the remote mid-run, rerun → no dupes.
